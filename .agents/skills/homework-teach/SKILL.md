# Teach the reasoning

Read AGENTS.md and verify the authorized library. Use [private routing](references/routing.md) for email or a new library. Inspect all pages, diagrams and givens privately. Use safe readers and the [DOCX helper](scripts/read-docx.py) for body text. Check Word visuals separately. Ask about essential illegible details. Keep inputs, learner records and comparisons outside the public checkout.

Route by the required reasoning. Load the subject skill in subjects.json or [create it](references/new-subject.md). Correct a mismatched direct invocation once. Separate distinct subjects, link needed continuations, and reuse matching URLs.

## Author the lesson

Before drafting, identify the response the assignment requires and the decisions a learner at this level must make. Search education research or evidence-based teaching guidance for specific misconceptions, errors, or sticking points in those decisions. Use generic queries that omit assignment text and learner details. Check whether the evidence applies to this task and level. Use relevant findings to shape a worked contrast, diagnostic prompt, feedback, or retry. Keep the evidence and the design choice private. If relevant evidence is limited, record that and proceed with the best supported approach.

Use GPT-6.1 Sol High. Draft privately from templates/lesson.html with shared assets. Privately map each required cue, decision and response to a worked example and an uncued attempt. Preserve the task's input and response demands while changing the content. Try the hardest practice without its hints. Revise if a simpler shortcut bypasses the required decision. Use a short main route of required methods. Put optional support and post-attempt comparisons behind disclosures. For a combined lesson, rebuild the prerequisite route from its own entry point and place needed lookups or support links at the activity that uses them. Match sentence length, vocabulary and step size to the stated grade or course, or infer the level from vocabulary and prerequisites. Record missing source limits privately.

- Start with a short prerequisite check and a bridge if needed, including labels or methods the independent task will require. In the smallest worked example, establish what must hold, then derive the key move from it. Briefly define terms on first use and link each glossary term to its entry there. Mark language changes. Use the task’s conventional notation in worked steps, interactive states, feedback and fallbacks. In calculations, separate givens and goal, show one justified step per line, and use equality and approximation precisely. Carry units through each step or name the unit of the numerical calculation.
- Compare every example, hint, reveal, caption, and feedback message with the assignment. Change the context, structure and cues while preserving the reasoning. Leave assigned answers and confirmations to the learner. Teach a prerequisite or alternate case if the definition would answer the question.
- Use labeled, accurate visuals with text equivalents and model limits. If changing a variable or cue helps, ask for a prediction, let the learner test it, then explain. Put the prediction before result-producing controls in both reading and keyboard order at every layout. Provide keyboard controls, reset or replay, reduced motion and readable print. At phone width, enlarge text and inspect whole formulas, headings, controls and labels inside diagrams. Match visible control labels to their accessible names. In print, keep each blank task with its complete evidence and instructions. Put its comparison on a later page or in a separate answer section; this includes warm-ups, predictions and retries, not only the final worksheet. Keep worked teaching together.
- Choose layout per activity. Use an Evidence Split when learners repeatedly consult the same concrete problem, diagram, or givens while following reasoning. Put the complete current task evidence in one pane and its reasoning or response activity alongside it. Here, the current task is an original worked example or practice task. A generic reference or earlier example cannot stand in for it. Give distinct tasks their own relevant evidence. Keep narrative, extended reading, and writing in ordinary reading flow; compact source analysis may benefit from a split. On narrow screens, keep corresponding evidence and tasks together and adapt navigation to their actual visibility.
- For each major decision, supply the required input in the form requested and ask for an action. Keep the outcome in a closed comparison or show it after a check. Make feedback actionable: demonstrate repairing a plausible weak response, ask the learner to revise their own reasoning, then give a fresh retry. End with uncued work, a short return checklist and a concrete later-recall prompt with its own fresh input.
- Write static task inputs and comparisons first. Keep required pre-attempt evidence available when enhancement fails. Keep predictions visible and comparisons closed. Enable controls only when feedback works without sending responses. Hide only duplicate comparisons. Keep practice in page memory. Test with scripts off and each owner blocked. Check both ends of any numeric tolerance.
- Put a visible Lesson library link to ../index.html near the top. Start with [RESOURCES.md](../../../RESOURCES.md) for a focused method or lookup reference. Open it in the browser used to test the lesson. State what it supports and cite displayed lookup data where it is actually supplied. Verify its guidance and data, and compare its reachable examples, reveals and practice with the assignment. If it fails to load or exposes an assigned answer, use a narrower verified source.

For follow-up, ask what is unclear and use a fresh prerequisite check. Offer a hint or checking method for assigned work. Begin a return visit with recall and transfer.
