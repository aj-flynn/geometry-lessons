# Test and refine skills

Use this workflow when maintaining the teaching skills. Everyday generation uses the lesson workflow.

1. Select real assignments spanning different reasoning, formats and subject routes. Use authorized private work and public practice. Set aside unseen assignments before editing. Keep inputs, source maps, drafts and raw reviews outside the checkout.
2. Give fresh GPT-6.1 Sol High authors the candidate skills, template, assets and one assignment each. Withhold prior pages, findings and scores. Capture the first HTML produced under the normal workflow before evaluation or manual fixes.
3. Freeze the skills, outputs, dependencies and sources. Have a fresh GPT-6 Astra agent score lesson and process separately with the [rubric](../../../../docs/REVIEW-RUBRIC.md). Compare actual teaching, source separation and learner operations. Target 100/100 for each lesson and the exercised process. After Astra reaches the target, have Claude Code score the same candidate independently with --model claude-opus-5-5 --effort medium --no-session-persistence. Verify modelUsage. Send private inputs to an external reviewer only with specific authorization. Each review starts fresh and receives no prior verdicts.
4. Translate supported findings into the smallest shared or subject rule that could prevent recurrence. Regenerate with fresh authors and use withheld assignments to check transfer before accepting the change. Track first-draft scores and material failures by sample. Keep rubric and scope stable when comparing scores. If stuck, ask a fresh independent agent for at least three untried approaches and test the strongest.
5. Use fork_turns: "none" for agents. Keep actual scores and limitations. Verify exact release bytes with scripts/review-candidate.mjs and publish demonstrated skill and lesson improvements through the normal publication checks. Preserve live URLs. Publish original teaching only.
