# Review and publish

Apply the [shared skill](../SKILL.md) to the exact lesson and its local dependencies. The author performs steps 1–4, then a separate reviewer subagent, started fresh, independently checks them before publication. Give the reviewer the source, frozen draft and dependencies, rubric, and raw browser evidence without author conclusions or prior verdicts. Include the hardest source cue, decision, grade-level demand and required response in the comparison. Use one focused independent pass. Correct material privacy, assigned-answer, subject-correctness or core-usability findings and recheck only affected tasks. Cosmetic suggestions and optional test limitations do not hold delivery. Do not run iterative scoring loops or require a numerical score. During skill refinement this is the scoring pass, not a second duplicate review. Keep source maps and comparisons private.

Include evidence for each lesson-specific script and state any unavailable source media or review limitations. When reusing browser evidence, identify its tested files and explain why later changes leave that behavior unaffected; provide new checks for affected consumers. A missing receipt in the review handoff is not evidence that a check ran or that the feature failed.

1. Compare every visible or hidden example, hint, answer key, feedback attribute, glossary, and direct learner destination against the supplied assignment. Inspect filenames, comments, metadata, visuals and text alternatives for privacy and homework separation.
2. Verify claims, arithmetic, notation, units, theorem conditions, assumptions, representation agreement, and credible sources. Read worked steps in order and check that each relation is valid. Trace each glossary term to its first meaningful use, with comparisons closed. Check that each required decision has original practice and a way back to independent work. Compare core instructions, examples and feedback with the grade or course demands.
3. In the rendered browser, attempt a representative core learner task with hints and answers closed, using only the supplied content and intended controls or links. Verify that the required evidence is available in the intended form and current interactive state, the action and required response are clear, and the outcome has not been revealed prematurely in visible content or accessible names and descriptions. A task that asks learners to inspect a visual needs that visual present and readable; a clearly framed text-only scenario can supply its evidence in words. Then reveal the feedback and confirm that it addresses the same task, givens, labels, diagram state, and requested response. Keep concise private notes of each task attempted, the evidence actually available, and any mismatch and correction. Reattempt corrected tasks before passing this step. Screenshots and passing technical checks support this review; they do not establish that a task makes sense.

   For targeted deeper review when a concrete risk or change warrants it (not a routine release gate), reattempt visual prompts through their text alternatives before opening feedback. For each activity, check that the layout fits the evidence-use pattern and that any persistent pane contains that activity's actual evidence. When the task changes, verify that its evidence changes with it. Repeat these attempts in wide and narrow layouts. Check that each navigation control serves a useful purpose and that instructions match the actual position and visibility of content. Adapt or omit misleading directions and redundant navigation when content becomes pinned, stacked, reordered, or hidden. Verify that layout-specific aids appear where needed, record the layout with any mismatch, and recheck both layouts after corrections.

4. Perform a proportionate browser smoke test: confirm readable content at desktop and narrow widths, working core controls and links, keyboard access, feedback and visible focus. Exercise additional modes only when supported and relevant; do not move the lesson to another computer solely to run optional checks. If testing enlarged text, confirm it actually enlarges; changing a setting alone does not establish this. When testing narrow widths, check that tables remain readable without pushing the whole page sideways; any needed table scrolling must work by keyboard. In each tested fallback mode, reattempt tasks whose inputs or feedback change, with comparisons closed; working disclosures alone do not prove that the task's inputs survive. Check actual page behavior including library return, no response requests or storage, and meaningful fallback. Repeat affected checks for consumers of changed shared assets. Report observed limits without treating unavailable optional modes as failures. Block only a concrete material defect in core use, correctness, privacy or homework separation.
   For each slideshow (div.deck[data-deck]), step through every slide with Next, Back, the arrow keys and Home/End; confirm the step count and title are announced, every slide's diagram matches its text, and the steps list below it gives the same method with a reason in each closed "Why?". With scripts off, confirm every slide is visible as a numbered sequence. For a labeled definition diagram, confirm every defined term is drawn, labeled and located in its definition.
   Temporary review scope (owner-directed, 2026-11-17): actual reduced-motion preference testing and paginated-print inspection are not required release checks until the owner reinstates them. Keep reduced-motion support, motion controls, print styles and readable-print authoring guidance intact. Continue the core smoke test; other accessibility and fallback modes are targeted checks when supported and relevant, not mandatory release gates. Record these two checks as out of scope, not passed; do not claim complete accessibility or print verification. An issue actually observed in either behavior must still be reported.

5. Update version-2 lessons.json with the lesson's library (see [routing](routing.md)), the registered subject, public title/summary/topics, and truthful privacy, homeworkSeparation and accuracy attestations. Record accessibility=true only when supported; otherwise use coreUsability=true with explicit limitations after the core-use pass. This scoped attestation is not full accessibility conformance. Keep existing filenames; number new lessons sequentially across the whole site, since every library shares lessons/. Preserve legacy Geometry compatibility. Preserve historical review records when guidance changes; do not migrate old lesson claims or scores just to match current instructions. Hash LF-normalized HTML bytes and obtain review.dependencies and review.contract using collectLessonDependencyHashes(base, file) and collectReviewContractHashes(base, subject) from scripts/check.mjs. The closure includes local references and transitive assets. Refresh claims only after review.
6. Use the static loading convention. Put literal, semicolon-terminated local imports at the start of scripts. Bind events with addEventListener. Use literal local CSS resources. Keep dynamic loading, inline handlers, embedded documents, navigation tricks, and response tracking out of learner pages. The checker is a guard; inspect meaning and executable behavior.
7. On a fresh checkout use npm ci --ignore-scripts. Rebuild with node scripts/build-index.mjs, then run node scripts/check.mjs and node --test tests/*.test.mjs. Run affected browser checks in the [README](../../../../README.md).
8. Inspect the explicit staged paths and commit text for privacy. Recheck the authorized destination, publish reviewed lesson, skill, dependencies, manifest and every changed library's index.html, feed.xml and feeds/ together, and run check-live.py against that site where Python Playwright is available. Otherwise open the lesson's live library and the lesson in a browser at desktop and phone widths, step a slideshow, and confirm that library's feed.xml parses. Verify reviewed bytes and actual keyboard navigation. Verify deployment before giving the lesson and library URLs through the approved originating route. Report any pending delivery.
