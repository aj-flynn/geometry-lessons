# Review and publish

Apply the [shared skill](../SKILL.md) to the exact lesson and its local dependencies. The author performs steps 1–4, then a fresh GPT-6 Astra reviewer independently checks them before publication. Give the reviewer the source, frozen draft and dependencies, rubric, and raw browser evidence without author conclusions or prior verdicts. Include the hardest source cue, decision, grade-level demand and required response in the comparison. Correct supported findings and have the reviewer reattempt affected tasks; unresolved material findings block publication. During skill refinement this is the scoring pass, not a second duplicate review. Keep source maps and comparisons private.

1. Compare every visible or hidden example, hint, answer key, feedback attribute, glossary, and direct learner destination against the supplied assignment. Inspect filenames, comments, metadata, visuals and text alternatives for privacy and homework separation.
2. Verify claims, arithmetic, notation, units, theorem conditions, assumptions, representation agreement, and credible sources. Read worked steps in order and check that each relation is valid. Trace each glossary term to its first meaningful use, with comparisons closed. Check that each required decision has original practice and a way back to independent work. Compare core instructions, examples and feedback with the grade or course demands.
3. In the rendered browser, attempt every learner task with hints and answers closed, using only the supplied content and intended controls or links. Verify that the required evidence is available in the intended form and current interactive state, the action and required response are clear, and the outcome has not been revealed prematurely in visible content or accessible names and descriptions. A task that asks learners to inspect a visual needs that visual present and readable; a clearly framed text-only scenario can supply its evidence in words. Then reveal the feedback and confirm that it addresses the same task, givens, labels, diagram state, and requested response. Keep concise private notes of each task attempted, the evidence actually available, and any mismatch and correction. Reattempt corrected tasks before passing this step. Screenshots and passing technical checks support this review; they do not establish that a task makes sense.

   Reattempt visual prompts through their text alternatives before opening feedback. For each activity, check that the layout fits the evidence-use pattern and that any persistent pane contains that activity's actual evidence. When the task changes, verify that its evidence changes with it. Repeat these attempts in wide and narrow layouts. Check that each navigation control serves a useful purpose and that instructions match the actual position and visibility of content. Adapt or omit misleading directions and redundant navigation when content becomes pinned, stacked, reordered, or hidden. Verify that layout-specific aids appear where needed, record the layout with any mismatch, and recheck both layouts after corrections.

4. Exercise keyboard use, contrast, focus, feedback, responsive reflow, actual browser zoom and enlarged text, motion controls, no JavaScript, individual script failure, and print. Confirm that rendered text actually enlarges; changing a setting alone does not establish this. At narrow widths, check that tables remain readable without pushing the whole page sideways; any needed table scrolling must work by keyboard. In each fallback mode, reattempt tasks whose inputs or feedback change, with comparisons closed; working disclosures alone do not prove that the task's inputs survive. Inspect the paginated printout: diagram labels remain readable, a task's evidence and complete instructions stay together, and short glossary entries do not split between term and definition. For work performed on paper, check that the comparison does not preempt the blank attempt. Check actual page behavior including library return, no response requests or storage, and meaningful fallback. Repeat affected checks for every consumer of changed shared assets. Report observed limits.
5. Update version-2 lessons.json with the registered subject, public title/summary/topics, and truthful privacy, homeworkSeparation, accuracy, and accessibility attestations. Keep existing filenames; number new lessons sequentially within the library. Preserve legacy Geometry compatibility. Hash LF-normalized HTML bytes and obtain review.dependencies and review.contract using collectLessonDependencyHashes(base, file) and collectReviewContractHashes(base, subject) from scripts/check.mjs. The closure includes local references and transitive assets. Refresh claims only after review.
6. Use the static loading convention. Put literal, semicolon-terminated local imports at the start of scripts. Bind events with addEventListener. Use literal local CSS resources. Keep dynamic loading, inline handlers, embedded documents, navigation tricks, and response tracking out of learner pages. The checker is a guard; inspect meaning and executable behavior.
7. On a fresh checkout use npm ci --ignore-scripts. Rebuild with node scripts/build-index.mjs, then run node scripts/check.mjs and node --test tests/*.test.mjs. Run affected browser checks in the [README](../../../../README.md).
8. Inspect the explicit staged paths and commit text for privacy. Recheck the authorized destination, publish reviewed lesson, skill, dependencies, manifest and index together, and run check-live.py against that site. Verify reviewed bytes and actual keyboard navigation. Verify deployment before giving the lesson and library URLs through the approved originating route. Report any pending delivery.
