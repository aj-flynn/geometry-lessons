# Create and test a subject skill

Use this branch when the supplied homework's subject is absent from `subjects.json`, or its registered skill is missing. Identify the subject from the source's concepts, not its filename alone. If a real ambiguity would change the teaching, ask a focused question while continuing independent preparation.

1. Read the available skill-creator and writing-for-agents instructions. Create `.agents/skills/<subject-id>-teach/SKILL.md` with matching `name`, a subject-specific invocation description, and a link to the shared homework-teach contract. Use a lowercase hyphenated public subject ID unrelated to a learner or sender. Identify a distinct discipline before considering the broad Science route: Physics and Biology each require their own skill when absent; genuinely integrated science can use Science.
2. Write reusable subject decisions: prerequisite progression; reliable sources; common misconceptions; domain correctness and notation; useful visuals and interactions; meaningful transfer; and subject-specific ways that an explanation could complete the assignment. For Spanish, for example, attend to register, regional variation, accents, agreement, and original communicative contexts rather than translating assigned sentences. Tailor the actual skill to the actual supplied material without embedding it.
3. Add `{ "id": "spanish", "label": "Spanish", "skill": ".agents/skills/spanish-teach/SKILL.md" }` to the selected library's ordered `subjects.json` only when creating that subject. The registry drives manifest validation, index grouping, and permitted skill paths; no JavaScript subject-list edit is needed. Existing labels and lesson URLs remain valid. Register the real subject, not a generic catch-all that hides missing guidance.
4. Validate frontmatter and links with skill-creator's validator where available. Generate or revise a lesson using the supplied private homework and the new skill. Use a fresh agent to exercise routing and the skill on representative requests, including an unknown subject and a follow-up request. Check observable behavior and boundaries rather than matching wording.
5. Apply [independent refinement](independent-refinement.md) to the lesson and reusable process. Feed demonstrated process failures back into the subject skill; improve shared guidance only for a cross-subject invariant. Publish independently improved skill revisions with the associated reviewed lessons, registry, and index. A valid skill file alone is not evidence of teaching quality.

Keep the complete shared privacy, no-answer, source, accessibility, and publication contract in homework-teach. Subject skills reference it once and contain domain guidance rather than copies of it. A direct invocation first verifies that its subject matches the source; a mismatch returns once to the router, while a match continues without a recursion loop. Skills and registries belong to their authorized library. Copying a reusable skill to a separately authorized library requires that library's own validation and review; do not silently synchronize public changes across private sender partitions.
