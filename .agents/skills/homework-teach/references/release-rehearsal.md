# Record the evidence and rehearse the release

Use one private execution record outside the public repository for the current run. Keep source locations, source comparisons, routing identities, observed learner state and raw reviewer output there. Public review records contain only sanitized findings, scores, public artifact hashes and truthful delivery status. This record coordinates the existing teaching and review steps; it adds no permission to publish or disclose input.

## Establish what can be assessed

For each affected lesson, record the actual subject, authorized library, current source availability, relevant earlier source availability, changed teaching decisions, and the permitted work while dependencies are missing. Classify evidence as actual-source generation, an explicitly synthetic diagnostic, or an instruction-level exercise.

When replacing an existing lesson URL for a new assignment, privately compare changed examples and teaching with both the current supplied work and relevant earlier source context. Use authorized original locations or existing private context; do not make a public source history. If the earlier source is unavailable and the change could invalidate its separation review, obtain that source through an authorized route or defer the affected teaching change. Do not refresh that separation claim or use a new URL merely to bypass it. Unchanged lesson bytes can retain their exact earlier bounded provenance; source-independent tooling review is a separate claim.

For a shared teaching change without representative input for an affected subject, leave that teaching change undeployed for that lane: scope it to tested subjects or defer it. Continue independently reviewed infrastructure work where it does not change those teaching decisions. A synthetic diagnostic may exercise an otherwise untested branch, but it never becomes user homework or evidence of actual-assignment alignment. Keep its source and produced teaching outside the public library, label it synthetic throughout, and report actual-source coverage separately.

## Produce and identify the candidate

Generate the affected teaching from the revised skill and authorized source, then perform the semantic review. Record the concept, fresh transfer, misconception feedback and source-check evidence privately so another reviewer can inspect the actual teaching decisions. Use the existing private record to retain attempted approaches, observed failures and the chosen alternative. Complete the reviewed lesson/dependency/contract maps and generated index before freezing.

Freeze an explicit selected Git tree or an equivalent complete candidate directory. Include all governing instructions, lesson/reference assets, templates, registry, manifest, index, scripts, tests, lockfile and rubric in a private whole-candidate path/hash receipt. Per-lesson maps remain useful; the complete receipt also identifies tooling and governing files outside those maps. Keep receipts outside the public candidate and never hash a receipt into itself.

Designate the exact existing review-report paths allowed to receive results before review starts. Freeze their existing bytes as a baseline; only inspected, sanitized append-only results may be added afterward. No lesson, executable, instruction, rubric, manifest or index is a report output. Both independent reviewers assess the same frozen inputs. Afterward, verify those inputs are unchanged, inspect the permitted report additions for privacy, and record the final publication tree separately. The assessed input identity and final publication envelope are different, explicit claims. Unexpected input changes return to Astra first.

Use `node scripts/review-candidate.mjs create <archive> <private-input-receipt> <report-paths...>` after completing candidate checks. The tool requires a frozen archive rather than a live Git checkout, records the complete input inventory, and accepts only the four existing subject/shared review records as optional append outputs. After the independent reviews and semantic inspection of report additions, run `node scripts/review-candidate.mjs verify <archive> <private-input-receipt> <private-publication-envelope>`. Both output files must be new and outside the archive. The verifier rejects changed input bytes, changed file membership, rewritten report prefixes, and common privacy violations. The private receipt's trusted custody is part of the execution record; its hash is an identity check, not a signature or proof that reviewers performed semantic work.

Do not silently omit unknown archive content. Git ignore rules never exempt selected or tracked files from publication review. Install pinned dependencies with scripts disabled as a separate tooling operation outside a frozen archive; an arbitrary preexisting directory named `node_modules` is not proof of a trusted install. Hidden scratch content and private input do not belong in a public candidate, including an ignored directory.

## Rehearse decisions and behavior

Run the structured [routing and refinement cases](routing-cases.md) with a fresh executor receiving only inputs, vocabulary and current instructions. Keep expected case associations withheld. Save the actual structured decisions privately, compare required and prohibited decisions, and investigate discrepancies. A matching record demonstrates those observed choices; it does not establish an installed router or future model behavior.

Exercise practice with JavaScript disabled and with failed initialization. Use synthetic response values and observe requests and URL changes. Confirm successful interaction keeps responses in memory and produces no storage or network side effect. Inspect the executable source for persistence and transmission capabilities too: finite browser observations cannot prove dormant code absent. Existing component behavior and real semantic review support the claim together; a blocklist alone does not.

Run the required repository checks and the live delivery helper against the final selected publication. Preserve observed results, failures, scope and inaccessible surfaces. The private record should make these distinctions visible: what was generated from an actual source; which synthetic or instruction branches were exercised; exactly which bytes were reviewed by which configured model and effort; which stage remains; and which publication actions are currently justified.

Reviewers retain the unchanged rubric and their independent judgment. Neither this receipt nor a structured observation is a machine proof of teaching quality, privacy, subject accuracy or learner mastery. Missing source access still leaves source-dependent claims unassessed; missing model access remains an access blocker.
