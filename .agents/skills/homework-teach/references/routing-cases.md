# Instruction-level routing rehearsal

Run affected cases when routing, authority, or publication decisions change. The committed [case fixtures](../../../../tests/fixtures/routing-cases.json) are synthetic decision situations. They contain no actual assignments or learner identities. The rehearsal creates no lessons, libraries, deliveries, or integrations.

1. Run `node scripts/check-routing.mjs inputs` to obtain the case IDs and inputs. Run `node scripts/check-routing.mjs codes` for the pooled decision vocabulary, which does not map codes to cases.
2. Give a fresh independent executor the current governing instructions, synthetic inputs, and pooled vocabulary. Export both lists from the frozen tooling. Withhold the fixture's per-case expectations, earlier observations, and the author's verdict. Keep the exercise read-only. Ask the executor to return a JSON array with one record per case, consisting of `case_id`, `subject_route`, `next_action`, `prohibited_action`, `evidence_needed`, and `explanation`. Select codes that apply to the given situation. Use free text to explain sequencing, conditions that could change the decision, and relevant qualifications the vocabulary does not capture.
3. Save the actual observations as JSON outside the public checkout, and run `node scripts/check-routing.mjs check <private-observations.json>`. The comparator checks case coverage, required codes, whether routes, actions and evidence apply to each case, and whether an action is prohibited. Inspect explanations for contradictions and authority expansion that the codes cannot express. Record genuine disagreements and the observed outcome privately.

A match is evidence of the coded decisions returned for these synthetic inputs. It cannot establish independent reasoning, teaching quality on private material, an installed integration, successful delivery, or future behavior. It supplies no lesson or process score. Re-exercise affected teaching separately with representative authorized material.
